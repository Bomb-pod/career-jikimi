# 테스트셋 v4 — 난이도 3단계 문맥 이탈 평가셋

- 파일: `test_dataset_v4_200.csv` (200행 / 100쌍)
- 생성: `python build_testset_v4.py --check ../dataset/training_dataset_v3_1000_simple.csv`
- 시드: `rooms_v4.py` (방 쌍 50개)
- 진단: `python overlap_baseline.py test_dataset_v4_200.csv`

## 왜 만들었나

기존 `test_dataset_100.csv`는 두 가지 문제가 있다.

**1. 문맥을 안 봐도 풀린다.** 부적절 50건 중 48건이 history와 어절 겹침이 0이다.
부적절 응답이 어휘가 통째로 다른 도메인에서 왔기 때문이다. 그 결과 모델 없이
글자 2-gram 겹침만으로 **AUC 0.961**이 나온다. 여기서 AUC 1.0을 받아도 모델이
문맥을 판단한다는 근거가 되지 않는다.

**2. 프로젝트의 자체 누수 검증을 통과하지 못한다.**
`validate_context_dataset.py` 기준 **response-only 정확도 0.860** (기준 ≤0.55).
응답 문장만 보고도 86%를 맞힌다는 뜻이다.

```
파일: test_dataset_100.csv
  response-only            acc = 0.860  [FAIL 기준 ≤0.55]
  history-only             acc = 0.500  [PASS]
  history 셔플+concat       acc = 0.560  [PASS]
  관계 특징(유사도+격식)      acc = 0.840
  관계 신호 존재 여부: NO
  판정: 실패
```

또 `turn_count`가 전부 3턴이라 긴 문맥은 한 건도 재지 못하고,
100행이지만 쌍 구조라 독립 문맥은 50개뿐이다.

## 구조

기존 `build_100_extended.py`의 **교차(swap)** 방식을 따른다.
두 대화방 A/B와 각 방에 자연스러운 응답 rA/rB를 준비하고 서로 맞바꾼다.

```
A방 : rA = 적절,  rB = 부적절
B방 : rB = 적절,  rA = 부적절
```

이 구조 덕분에 **모든 응답이 적절/부적절 양쪽 label로 정확히 한 번씩** 등장한다.
따라서 response만 보거나 history만 봐서는 label을 맞힐 수 없고,
label은 오직 (history, response) 관계에만 존재한다.

## 난이도

난이도는 **두 방을 얼마나 비슷하게 잡느냐**로 만들었다.

| 난이도 | 쌍 | 설계 | 예시 |
|---|---|---|---|
| easy | 30 | 도메인이 완전히 다름 | 도자기 공방 ↔ 서버 배포 |
| medium | 40 | 인접 도메인, 일정·예약·비용 어휘 일부 공유 | 회사 회식 ↔ 동아리 뒷풀이 |
| hard | 30 | **같은 도메인, 같은 선택지를 논의하되 결론만 반대** | 축구 동호회(용병 반대) ↔ 풋살 모임(용병 찬성) |

hard의 설계 원칙이 핵심이다. 두 방이 **같은 단어를 모두 포함**하되 결론만 다르게 한다.

```
A방  회장: 이번 주 경기는 11명 정원인데 두 명이 부족합니다.
     나: 용병을 부를까요?
     회장: 지난번에 용병 불렀다가 호흡이 안 맞았습니다.
     ...
     회장: 회원 등록된 분들로만 부탁드립니다.
     [적절]   그럼 용병 말고 회원 두 명한테 연락해보겠습니다.
     [부적절] 용병 두 명이면 채워지겠네요. 신청은 총무님이 하시나요?

B방  총무: 풋살장은 5대5라 열 명이면 됩니다.
     ...
     총무: 이번 주는 다들 일정이 있다고 합니다.
     총무: 용병 두 명 부르겠습니다.
     [적절]   용병 두 명이면 채워지겠네요. 신청은 총무님이 하시나요?
     [부적절] 그럼 용병 말고 회원 두 명한테 연락해보겠습니다.
```

두 history 모두 `용병`, `회원`, `두 명`을 포함한다. 어휘 겹침으로는 구분할 수 없고
**어느 쪽으로 결론이 났는지 읽어야만** 판정할 수 있다.

적절 응답이 history의 핵심 단어를 그대로 복창하면 그 자체가 겹침 신호가 되므로,
각 방의 history가 상대 방의 핵심 단어까지 함께 언급하도록 배치해 균형을 맞췄다.

## 검증 결과

### 어휘 겹침 베이스라인 (모델 없이 문자열 겹침만으로 판정)

| 구간 | n | 어절 Jaccard | response 포함률 | 글자 2-gram |
|---|---|---|---|---|
| **v4 전체** | 200 | 0.641 | 0.629 | 0.763 |
| v4 easy | 60 | 0.764 | 0.761 | 0.968 |
| v4 medium | 80 | 0.656 | 0.657 | 0.821 |
| **v4 hard** | 60 | **0.534** | **0.542** | **0.557** |
| 기존 test_100 | 100 | 0.836 | 0.837 | 0.961 |
| 학습셋 v3 | 1000 | 0.711 | 0.708 | 0.820 |

hard 구간은 **0.53~0.56, 사실상 우연 수준**이다. 문자열 겹침으로는 전혀 풀리지 않는다.
easy 구간이 0.968인 것은 의도된 것으로, 회귀 테스트용 바닥(sanity floor) 역할을 한다.

### 누수 검증 (`validate_context_dataset.py`)

```
파일: test_dataset_v4_200.csv  (200행, 부적절 50.0%)
  response-only            acc = 0.500  [PASS 기준 ≤0.55]
  history-only             acc = 0.500  [PASS 기준 ≤0.55]
  history 셔플+concat       acc = 0.480  [PASS 기준 ≤0.6]
  history+response concat  acc = 0.170
  관계 특징(유사도+격식)      acc = 0.605
  관계 신호 존재 여부: YES
  판정: 통과 — label은 history와 response의 관계에만 존재한다.
```

### 학습셋 누수

`training_dataset_v3_1000_simple.csv`와 history / response / (history, response) 쌍
중복이 모두 **0**. `no` 번호도 2001부터 시작해 학습셋(1~1000), 기존 테스트셋(1001~1100)과 겹치지 않는다.

### 분포

- label: 적절 100 / 부적절 100
- 독립 문맥(고유 방): 100개, 고유 response: 100개
- `turn_count`: 1턴 4행, 2턴 4, 3턴 44, 4턴 4, 5턴 52, 6턴 4, 7턴 26, 8턴 2, 9턴 52, 11턴 6, 13턴 2
  → 기존 테스트셋은 전부 3턴이었다. 5턴 이상이 **71%**로 긴 문맥을 실제로 잰다.
- 응답 길이: 적절/부적절 평균이 난이도별로 정확히 동일 (길이 단독 AUC = 0.500)

## 컬럼

| 컬럼 | 설명 |
|---|---|
| `no` | 2001부터 연번 |
| `pair_id` | `V4E01A` 형식 — V4 + 난이도(E/M/H) + 쌍 번호 + 방(A/B) |
| `turn_count` | history 줄 수 |
| `history` | `화자: 발화` 줄들, 구분자 CRLF. `나:`로 끝나지 않음 |
| `response` | 판정 대상 응답 (화자는 항상 `나`) |
| `label` | `적절` / `부적절` |
| `difficulty` | `easy` / `medium` / `hard` — **추가 컬럼** |
| `tag` | 방 쌍 주제 — 추가 컬럼 |
| `room` | `A` / `B` — 추가 컬럼 |

앞 6개는 기존 데이터셋과 동일한 스키마다. 뒤 3개는 분석용이며
`test_dataset_100_hard.csv`도 추가 컬럼을 갖고 있으므로 기존 벤치마크와 호환된다.

## 쓰는 법

**난이도별로 나눠서 보고할 것.** 전체 한 줄로 보면 easy가 점수를 끌어올려
hard에서의 실패가 가려진다.

**어휘 겹침 베이스라인을 모델 점수와 나란히 찍을 것.**
`overlap_baseline.py`가 그 용도다. 모델 AUC가 겹침 AUC보다 유의하게 높지 않으면
모델이 기여한 게 없다는 뜻이다. easy에서 모델 0.99 / 겹침 0.97이면 자랑할 게 못 된다.

**50:50이므로 precision은 낙관적이다.** 실사용 기저율(추정 1~5%)로 보정해서 볼 것.
FP가 0이어도 FPR이 0인 것은 아니다 — 0/100의 95% 상한은 약 3/100이다.

## 한계

- **hard 30쌍은 통계적으로 얇다.** 구간별 신뢰구간이 넓으니 소수점 차이로 모델을 비교하지 말 것.
- 합성 데이터다. 실제 채팅의 오타, 축약, 이모지, 연속 전송이 없다.
- 화자 역할이 `나: / 상대:` 2인 대화 위주다. 단체방 다자 대화는 다루지 않는다.
- easy 구간은 어휘 겹침으로 풀리므로 **모델 능력 측정용이 아니라 회귀 감지용**이다.
