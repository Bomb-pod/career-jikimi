# 파인튜닝 모델 배포 체크리스트

§9가 만드는 것은 **기술적으로 동작하는 모델**이다. 다만 지금 컨테이너는
그것을 실행할 수 없다 — 아래 네 가지가 빠져 있다.

## 0. §9가 주는 것

```
context_checker.zip  (약 300MB)
└── context_checker/
    ├── config.json
    ├── model.safetensors        299MB
    ├── tokenizer.json / tokenizer_config.json / special_tokens_map.json
    └── threshold.json           선택 threshold + 스윕 전량
```

§9의 검산 단계가 **저장 → 재로드 → 추론**을 실제로 해보므로,
`OK` 두 줄이 찍혔다면 파일 자체는 정상이다.

## 1. 배치

```
backend/models/context_checker/       ← 압축을 여기에 푼다
backend/app/judgment/local_encoder.py ← 이미 있음
```

`.dockerignore`는 `backend/models/`를 막지 않는다 (확인함).

## 2. `backend/requirements.txt` — **이게 없으면 전부 실패한다**

지금 컨테이너에는 `openai` SDK만 있고 **torch도 transformers도 없다.**
`local_encoder.py`의 `import torch`가 `ModuleNotFoundError`를 내고,
그것이 `ModelCall(ok=False)`로 잡혀 **모든 메시지가 `failed`로 전송된다.**
조용히 망가지는 종류의 실패다 — 앱은 뜨고 채팅도 되는데 판정만 전부 실패한다.

```
transformers>=4.48
torch
```

> `requirements.txt`는 **ASCII 전용**이다 (HANDOFF § ASCII 전용 파일 셋).
> 한국어 주석을 넣으면 한국어 Windows(cp949)에서 pip이 `UnicodeDecodeError`를 낸다.

## 3. `Dockerfile` 두 곳

**(a) CPU 전용 torch를 먼저 받는다.** 그냥 두면 PyPI 기본 빌드(CUDA 포함)를
받아 이미지가 3GB 넘게 커진다. 컨테이너에 GPU를 붙이지 않으므로 낭비다.

```dockerfile
# python-build 스테이지, 기존 pip wheel 줄 앞에
RUN pip wheel --no-cache-dir --wheel-dir /wheels \
      --index-url https://download.pytorch.org/whl/cpu torch
RUN pip wheel --no-cache-dir --wheel-dir /wheels -r requirements.txt
```

**(b) 모델을 이미지에 굽는다.** 바인드 마운트가 없는 구조라 COPY가 필요하다.

```dockerfile
# runtime 스테이지, COPY backend/app 근처
COPY backend/models ./models
```

이미지가 약 1.3GB 커진다 (torch CPU ~750MB + 모델 300MB + 의존성).

## 4. `.env`

```
AI_VERDICT_THRESHOLD=<threshold.json 의 threshold 값>
```

**어댑터가 임계값을 판단하지 않는 이유가 이것이다.** `judge()`가 이 값으로
판정해야 `judgment_logs.threshold`에 실제 쓴 값이 남아 재현이 된다.

`OPENAI_API_KEY`는 여전히 필수다 — `config.py`가 기본값 없는 필수 키로 두었고,
`report` 같은 다른 경로가 설정을 읽는다. 아무 문자열이나 넣어두면 된다.

## 5. `service.py` import 한 줄

```python
# from app.judgment.client import call_model
from app.judgment.local_encoder import call_model
```

되돌리려면 주석을 반대로 옮긴다.

## 확인

```bash
docker compose up -d --build      # 이미지가 커져 빌드가 길어진다

# 판정 한 건 — 채팅 UI 없이
docker compose exec app python -m app.judgment.try \
  --context "내일 배포 리허설 몇 시로 할까요?" "오전 10시면 될 것 같습니다" \
            "저는 10시 좋습니다" "롤백 절차도 봐주세요" \
  --candidate "오늘 저녁에 치킨 어때?"
```

점수와 지연이 나오면 연결된 것이다. **지연이 수십 ms로 찍히는지** 보라 —
초 단위면 CPU 스레드 설정을 봐야 한다.

```bash
docker compose exec app python -m app.judgment.report    # 라이브 지표
```

## 확인할 것 — 첫 요청 지연

컨테이너 기동 후 **첫 판정은 모델 로딩(300MB)을 포함**한다. 수 초가 걸릴 수 있고
`AI_TIMEOUT_SECONDS=4.0`을 넘길 수 있다. 어댑터가 지연 로드를 쓰므로,
데모 전에 `try`를 한 번 돌려 워밍업해 둔다.

필요하면 `main.py`의 startup에서 `local_encoder._load()`를 한 번 부르는 것도 방법이다.
그러면 기동이 몇 초 느려지는 대신 첫 사용자가 기다리지 않는다.

## 남은 위험

| 항목 | 상태 |
|---|---|
| **운영 threshold** | 미정. 50:50 데이터로 뽑은 값이라 실사용 기저율에서 precision이 다르다 |
| transformers 버전 | Colab 5.x로 저장하고 컨테이너 4.48로 읽는다. 로드가 깨지면 버전을 맞출 것 |
| CPU 추론 속도 | 미측정. 0.1B/120토큰이면 수십 ms 예상이나 확인 필요 |
| 이미지 크기 | 약 1.3GB 증가. 발표 환경에서 빌드 시간을 감안할 것 |
