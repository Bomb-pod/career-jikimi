# 메시지 전송 시 AI에 전달되는 값

`backend/app/judgment/prompt.py`의 `build_messages()`를 **실제로 실행해 뽑은 값이다.**
문서용으로 손으로 쓴 예시가 아니다.

## 상황

방 `서버TF` (참여자 3명). 사용자 `지환`(`sender_id=7`)이 잡담방과 착각해
업무방에 치킨 얘기를 보내려는 순간.

| 설정 | 값 | 출처 |
|---|---|---|
| `AI_CONTEXT_N` | 10 | `core/config.py` |
| `AI_VERDICT_THRESHOLD` | 0.7 | `core/config.py` |
| `AI_TIMEOUT_SECONDS` | 4.0 | `core/config.py` |
| `OPENAI_MODEL` | `gpt-4o-mini` | `core/config.py` |
| `TEMPERATURE` | 0.0 (고정, 환경변수로 못 뺌) | `judgment/constants.py` |

## 1. 전달되지 **않는** 것

먼저 이쪽이 중요하다. 아래는 서버가 갖고 있지만 **모델에 안 보낸다.**

| 값 | 왜 안 보내나 |
|---|---|
| `user_id` / 아이디 / 별칭 / `display_name` | FR-6.2·BR-6.2. 익명 라벨로 치환 |
| 방 이름 (`서버TF`) | 참여자·방 정보 미사용이 프로젝트 결정 |
| 참여자 수, 친구 관계 | 〃 |
| `created_at` / 타임스탬프 | 프롬프트에 시간 개념 없음 |
| `seq` | 로그(`context_from_seq`)에만 쓰고 프롬프트엔 안 실림 |

`sender_id`는 **"누가 말했나"가 아니라 "화자가 바뀌었나"를 계산하는 데만** 쓰이고,
`A`/`B`/`C` 라벨로 바뀐 뒤에야 프롬프트에 실린다. 이 라벨은 **이번 판정에만 유효한
순번**이라 다음 판정에서 같은 사람이 다른 글자를 받아도 된다.

## 2. system 메시지 — 매번 동일

```
당신은 채팅 메시지가 그 대화방의 문맥에 맞는지 판단합니다.

사용자는 여러 채팅방을 오가며, 가끔 방을 착각해 엉뚱한 방에 메시지를
보냅니다. 당신의 일은 그것을 보내기 전에 알아채는 것입니다.

## 판단 기준

주어진 대화의 흐름·주제·어조에 비추어, 보내려는 메시지가 이 방에서
나올 법한 말인지 판단하십시오.

## 판단하지 않는 것

- 메시지 내용 자체의 적절성(욕설·비방·민감정보 여부)은 판단하지 마십시오.
- 맞춤법·문장의 완성도는 판단하지 마십시오.
- 화제가 바뀌었다는 사실만으로 부적합하다고 보지 마십시오. 대화는
  자연스럽게 화제를 바꿉니다.

## 점수

0.0에서 1.0 사이의 부적합 점수를 매기십시오. 높을수록 이 방에
어울리지 않는다는 뜻입니다.

- 0.0 ~ 0.2  이 대화의 자연스러운 연장
- 0.3 ~ 0.5  화제는 바뀌었으나 같은 관계·상황에서 나올 수 있는 말
- 0.6 ~ 0.8  이 방의 성격과 어긋남
- 0.9 ~ 1.0  명백히 다른 방에 갈 메시지

## 표기

화자는 A, B, C로 익명 표기됩니다. 이 라벨은 이번 판단에만 쓰이는
순번이며 특정 인물을 뜻하지 않습니다.
```

> 이 문안은 `business-logic-model.md`에서 확정한 것을 그대로 옮긴 것이고,
> `prompt.py` 주석이 **빼면 안 되는 세 가지**를 못박아 뒀다 —
> "판단하지 않는 것" 3항목, "화제 전환만으로 부적합 아님", 점수 구간 4개의 언어적 설명.

## 3. user 메시지 — 매 전송마다 바뀌는 부분

### 케이스 A — 오발송 (문맥 부적합)

```
## 최근 대화

A: 내일 배포 리허설 몇 시로 할까요?
B: 오전 10시면 될 것 같습니다
C: 저는 10시 좋습니다. 스테이징 먼저 올릴게요
A: 그럼 10시로 잡죠. 롤백 절차도 한 번 봐주세요
B: 롤백은 alembic downgrade 한 단계로 정리해뒀습니다
C: 스테이징 DB 스냅샷도 떠둘까요?
A: 네 부탁드려요. 용량은 얼마나 되나요
C: 덤프가 약 400MB 정도입니다
B: 그 정도면 복원도 2분 안 걸립니다
A: 좋네요. 그럼 내일 10시에 봅시다

## 보내려는 메시지

B: 오늘 저녁에 치킨 어때? 양념 vs 후라이드
```

화자가 `A`(팀장) `B`(지환) `C`(동료)로 등장 순서대로 매핑됐다.
후보 발신자가 `sender_id=7`이고 문맥에 이미 `B`로 있었으므로 **같은 `B`를 쓴다.**

### 케이스 B — 정상 (문맥 적합)

```
## 최근 대화

A: 내일 배포 리허설 몇 시로 할까요?
B: 오전 10시면 될 것 같습니다
C: 저는 10시 좋습니다. 스테이징 먼저 올릴게요
A: 그럼 10시로 잡죠. 롤백 절차도 한 번 봐주세요
B: 롤백은 alembic downgrade 한 단계로 정리해뒀습니다
C: 스테이징 DB 스냅샷도 떠둘까요?
A: 네 부탁드려요. 용량은 얼마나 되나요
C: 덤프가 약 400MB 정도입니다
B: 그 정도면 복원도 2분 안 걸립니다
A: 좋네요. 그럼 내일 10시에 봅시다

## 보내려는 메시지

B: 복원 스크립트도 같이 올려둘게요. 10시 전에 확인 부탁드립니다
```

문맥 블록은 케이스 A와 **완전히 동일하다.** 마지막 한 줄만 다르다 —
그게 이 기능이 재는 것의 전부다.

### 케이스 C — 처음 말하는 사람

```
## 최근 대화

A: 내일 배포 리허설 몇 시로 할까요?

C: 저는 10시 좋습니다. 스테이징 먼저 올릴게요
A: 그럼 10시로 잡죠. 롤백 절차도 한 번 봐주세요
B: 롤백은 alembic downgrade 한 단계로 정리해뒀습니다
C: 스테이징 DB 스냅샷도 떠둘까요?
A: 네 부탁드려요. 용량은 얼마나 되나요
C: 덤프가 약 400MB 정도입니다
B: 그 정도면 복원도 2분 안 걸립니다
A: 좋네요. 그럼 내일 10시에 봅시다

## 보내려는 메시지

D: 저도 리허설 참여하겠습니다
```

`sender_id=33`은 최근 10개에 없다. 이때 **기존 라벨을 재사용하지 않고 `D`를 새로 준다.**
재사용하면 모델이 "이 방에서 이미 말하던 사람"으로 읽어, 처음 말하는 사람이
끼어든 상황과 구별할 수 없게 된다.

## 4. API 호출 전문

```python
client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": <2번 전문>},
        {"role": "user",   "content": <3번 전문>},
    ],
    response_format={
            "type": "json_schema",
            "json_schema": {
                    "name": "verdict",
                    "strict": true,
                    "schema": {
                            "type": "object",
                            "properties": {
                                    "score": {
                                            "type": "number"
                                    }
                            },
                            "required": [
                                    "score"
                            ],
                            "additionalProperties": false
                    }
            }
    },
    temperature=0.0,
)
```

`strict: true`가 **파싱 실패라는 실패 유형 자체를 없앤다** (BR-6.4).
스키마가 `score` 하나뿐인 것도 결정이다 — 근거 문장을 받으면 디버깅엔 좋지만
토큰과 지연이 늘고, 지금 필요한 건 점수다.

### 응답

```json
{"score": 0.93}
```

### 판정

`0.93 ≥ AI_VERDICT_THRESHOLD(0.7)` → **부적합** → 팝업:

> 이 방에 맞지 않는 것 같습니다. 그래도 보낼까요?

## 5. 판정 후 DB에 남는 것

프롬프트에 안 들어간 값들이 **여기엔 남는다.** 재현과 집계에 필요해서다.

| 컬럼 | 값 | 비고 |
|---|---|---|
| `room_id` | 5 | |
| `context_from_seq` | 41 | 실제로 모델에 넣은 문맥 범위 |
| `context_to_seq` | 50 | 〃 |
| `score` | 0.930 | `DECIMAL(4,3)`으로 반올림 |
| `threshold` | 0.700 | 나중에 임계값을 바꿔도 이 판정을 재현할 수 있게 |
| `latency_ms` | 1180 | NFR-1 실측용 |
| `prompt_tokens` / `completion_tokens` | 412 / 8 | 비용 추적 |
| `user_action` | `sent` 또는 `cancelled` | **사실상의 정답 라벨** |
| `message_id` | NULL (취소 시) | 취소된 메시지는 `messages`에 안 남는다 |

## 6. 인코더 경로는 입력이 다르다

같은 상황을 A.X-Encoder에 넣으면 이렇게 된다.

```python
tokenizer(
    "A: 내일 배포 리허설 몇 시로 할까요?\nB: 오전 10시면 될 것 같습니다\n... (10줄)",
    "오늘 저녁에 치킨 어때? 양념 vs 후라이드",
    truncation="only_first",   # 잘릴 땐 문맥 앞부분부터. 판정 대상은 온전해야 한다
    max_length=384,
)
# -> [CLS] 문맥 [SEP] 후보 [SEP]  ->  P(부적절) = 0.93
```

| | LLM (`gpt-4o-mini`) | 인코더 (A.X-Encoder) |
|---|---|---|
| 입력 | system + user, 자연어 지시 | `(문맥, 후보)` 두 덩어리 |
| 화자 라벨 | `A:` `B:` 필요 (지시문이 설명) | 학습 데이터 형식을 따름 |
| 지시문 | 약 400 토큰 매번 전송 | **없음** (가중치에 학습됨) |
| 출력 | JSON `{"score": …}` | softmax 확률 |
| 지연 | 1~3초 + 네트워크 | 수십 ms, 로컬 |
| 외부 전송 | **최근 10개가 OpenAI로 나감** | 나가지 않음 |

마지막 줄이 README §프라이버시가 고지하기로 한 항목이고,
인코더로 갈아타면 그 고지 자체가 필요 없어진다.

## 직접 확인하는 법

```bash
# 키 없이 조립 결과만 (익명화 확인용)
docker compose exec app python -m app.judgment.try \
  --context "내일 배포 리허설 몇 시로 할까요?" "오전 10시면 될 것 같습니다" \
  --candidate "오늘 저녁에 치킨 어때?" --show-prompt --dry-run
```

`--show-prompt`가 조립된 프롬프트를, `--dry-run`이 **키 없이도** 익명화 결과를 보여준다.
