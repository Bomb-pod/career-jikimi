# 판정 성능 보고 — A.X-Encoder 파인튜닝 모델

측정일 2026-07-31 · `skt/A.X-Encoder-base` 파인튜닝(v3 1000행, 화자 익명화) ·
threshold 0.7 · CPU 추론

## 요약

**설계 범위 안에서는 완벽하고, 범위 밖에서는 거의 못 잡는다. 그리고 못 잡을 때
오탐을 내지 않는다.**

| | 오발송 탐지 (`test_dataset_100`) | 지시 위반 (`test_dataset_100_hard`) |
|---|---|---|
| AUC | **1.000** | 0.728 |
| 정확도 | **1.000** | 0.510 |
| **precision** | **1.000** | **1.000** |
| recall | **1.000** | **0.020** |
| 오탐(FP) | **0** | **0** |
| 절제 하락폭(AUC) | +0.362 → **문맥 사용** | +0.232 → 부분 사용 |
| p50 지연 | 512ms | 375ms |

두 평가셋 모두 학습 데이터와 **중복 0건**이다
((history, response) / response / history 전부 0/100).

## 1. 오발송 탐지 — 설계한 범위

`test_dataset_100` 100행 (적절 50 / 부적절 50).

```
AUC 1.000 | 정확도 1.000 | precision 1.000 | recall 1.000
FP 0 | FN 0 | 팝업률 0.500
```

### 점수가 완전히 갈렸다

| | 중앙값 | 최소 | 최대 |
|---|---|---|---|
| 부적절 | 0.9916 | **0.8481** | 0.9985 |
| 적절 | 0.0032 | 0.0007 | **0.1613** |

두 집단 사이에 **0.687의 빈 구간**이 있다. threshold를 0.20~0.80 어디에 두어도
정확도가 1.000이다.

**0.7을 택한 이유** — 적절 쪽 여유(0.539)가 부적절 쪽(0.148)보다 크다.
false positive가 치명적이라는 우선순위(README)에 맞춘 비대칭 선택이며,
`config.py`의 기존 기본값이라 설정 변경도 필요 없다.

### 절제 실험 — 문맥을 실제로 읽는다

응답은 그대로 두고 history만 다른 행 것으로 바꿔 다시 판정했다.

```
AUC    1.000 → 0.638   (-0.362)
정확도 1.000 → 0.550   (-0.450)
```

문맥을 망가뜨리자 판별력이 무너진다. **정확도가 응답 문체 암기에서 온 것이
아니라는 직접 증거다.**

## 2. hard 셋 — 설계 범위 밖

`test_dataset_100_hard` 100행. 부적절 50건이 네 유형으로 나뉜다.

| reason | 건수 | 잡은 것 | 정의 |
|---|---|---|---|
| N4 | 40 | **0** | 명시된 조건·제한사항 위반 |
| N3 | 4 | 1 | 요청의 핵심을 처리하지 않음 |
| N1 | 4 | **0** | 시간·순서·대상이 이전 문맥과 불일치 |
| N2 | 2 | **0** | 이전 발화의 정보를 잘못 해석 |
| **P5** | **50** | **50 전부 정답** | 적절 — **오탐 0** |

### N4가 안 잡히는 것은 정상이다

N4 예시:

> history: "기존 API는 **유지**하고 관리자 조회 API만 추가해주세요"
> response: "기존 API를 **삭제**하고 새 API로 교체하겠습니다"

**같은 방, 같은 주제다.** 방을 착각한 게 아니라 지시를 잘못 따랐다.
판정 프롬프트가 명시한 대로 —

> "메시지 **내용 자체의 적절성**은 판단하지 마십시오"

`dataset-v2-notes.md`도 같은 결론을 이미 기록했다:
"N2~N5는 범위 밖. `pragmatic_quality_dataset_v2.csv`로 분리 보존(향후 톤 경고 확장용)."

**부적절 50건 중 46건(92%)이 이 범주다.** recall 0.020은 기능 실패가 아니라
**다른 능력을 측정한 결과**다.

### 그런데 N1도 못 잡았다 — 이건 새로운 발견이다

N1은 "문맥 불일치"라 프로젝트 정의에 가장 가깝다. 그런데 0/4다.

> history: "금요일 약속은 어렵고 **토요일** 오후가 가능합니다"
> response: "**금요일** 저녁으로 약속을 잡자"

이것도 **같은 방, 같은 화제**다. 어긋난 것은 방이 아니라 **세부 정보**다.

학습 데이터(v3)의 부적절은 전부 **cross-room**(다른 방 문맥과 결합)이다.
v2.5의 hard negative 4쌍조차 "같은 도메인 **다른 방**"이었지
"**같은 방 안**의 사실 모순"은 한 건도 없었다.

**모델은 배운 적 없는 종류를 못 잡은 것이다.** 데이터셋의 구조적 한계이며,
확장하려면 "같은 history + 세부만 어긋난 response" 쌍을 새로 만들어야 한다.

### 실패 방식이 안전하다

hard 셋에서 팝업률이 **0.01**이다. 50건 중 1건만 플래그했고 그것도 정답이었다.

**모르는 종류를 만나면 조용히 넘어간다.** 함부로 팝업을 띄우지 않는다.
precision이 우선 지표인 설계에서 이것이 올바른 실패 모드다 —
범위 밖 입력에서도 오탐 0을 유지했다.

AUC 0.728이 우연(0.5)보다 높은 것은 점수 **순위**는 어느 정도 맞다는 뜻이다.
threshold를 낮추면 recall이 오르겠지만, 그 대가로 오발송 탐지의 precision을
잃는다. 두 태스크에 threshold 하나를 공유할 수 없다.

## 3. 지연 — NFR-1

| | p50 | p95 | 4초 초과 |
|---|---|---|---|
| 오발송 셋 | 512ms | 534ms | **0건** |
| hard 셋 | 375ms | 377ms | **0건** |

`AI_TIMEOUT_SECONDS=4.0` 기준 **초과 0건**. NFR-1(정상 5초)을 여유 있게 지킨다.

**단, 이 값은 배치 32 처리량이다.** 실서비스는 한 건씩 오므로 단일 요청 지연을
따로 재야 한다 (`app.judgment.try`로 확인).

또한 첫 호출은 모델 로딩(299MB)을 포함해 수 초가 걸린다 —
`main.py` lifespan의 `backend.warmup()`이 그것을 기동 시점으로 옮긴다.

## 4. 믿으면 안 되는 숫자

### `prec@1% = 1.000`

적절 50건 중 FP가 0이라 FPR을 0으로 계산한 결과다. **0/50이 FPR=0을 뜻하지 않는다.**
0/50의 95% 상한은 약 0.060(rule of three)이고, 그 값으로 다시 보면:

| 기저율 | 오발송 셋 | hard 셋 |
|---|---|---|
| 10% | 0.649 | — |
| 5% | 0.467 | — |
| **1%** | **0.144** | **0.003** |

**실사용에서 오발송이 1%라면 팝업 7번 중 6번이 오탐일 수 있다.**
100행으로는 이 이상 좁힐 수 없다 — 더 많은 "적절" 표본이 필요하다.

### AUC 1.000

`test_dataset_100`은 짝 구조가 없어 **response-only만으로 0.840**이 나오는
데이터다. 응답 표면 신호가 강해 난이도가 낮다. 학습 OOF가 0.832였던 것과
대비하면, 이 평가셋이 학습 데이터보다 **쉬웠다**고 보는 편이 정확하다.

## 5. 결론

**확정된 것**

1. 오발송 탐지에서 완전 분리 (AUC 1.000, 점수 간격 0.687)
2. 절제 실험이 문맥 사용을 확인 (AUC 1.000 → 0.638)
3. 지연 512ms — 4초 예산의 1/8, 외부 전송 없음
4. **범위 밖 입력에서도 오탐 0** — 안전한 실패

**확정되지 않은 것**

1. 실사용 precision — 기저율을 모른다. `judgment_logs.user_action`이 답한다 (FR-7.5)
2. 단일 요청 지연 — 배치 처리량만 쟀다
3. 더 어려운 오발송(같은 도메인·다른 방)에서의 성능 — 평가셋에 그 슬라이스가 없다

**다음 확장 후보**

같은 방 안의 사실 모순(N1형)은 현재 데이터셋이 다루지 않는다.
넣으려면 "같은 history + 날짜·인명·수량만 어긋난 response" 쌍을 설계해야 하고,
그것은 오발송 탐지와 별개의 능력이다.
