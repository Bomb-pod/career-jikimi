## 오늘의 핵심 — 익명화가 일반화를 개선했다

학습 데이터의 `history`는 `선임:` `팀장:` 같은 실제 호칭을 쓴다(66종). 그런데
웹앱은 FR-6.2에 따라 `A:` `B:`로 익명화해서 모델에 넣는다.
**그대로 학습하면 배포 시 학습에서 한 번도 못 본 형식이 들어간다.**

형식을 맞추려고 익명화를 넣었는데, 같은 fold(seed 42 · fold 1)로 비교하니
성능까지 올랐다.

| | 학습셋 | 검증 | 격차 |
|---|---|---|---|
| 익명화 전 | 0.905 | 0.855 | +0.050 |
| 익명화 후 | 0.885 | **0.890** | −0.005 |

호칭 66종 중에는 특정 방에만 나오는 이름(민규 98회, 다연 98회)도 있어
**암기 손잡이** 역할을 하고 있었다. 지우니 학습셋은 내려가고 검증은 올라갔다.
과적합 격차가 사실상 0이 됐다.

같은 방·같은 주제다. 프롬프트가 명시적으로 배제한 범주이고

"N2~N5는 범위 밖"으로 분리해뒀다.

**새로 알게 된 것 — N1(4건)도 0/4다.** N1은 "문맥 불일치"라 정의에 가깝지만
실제로는 *같은 방 안에서 날짜·대상만 어긋난* 경우다. v3의 부적절은 전부
cross-room이라 **모델이 배운 적 없는 종류**다. 데이터셋의 구조적 한계.

**실패 방식이 안전하다.** hard 셋 팝업률 0.01 — 모르는 종류를 만나면 조용히
넘어가고 오탐을 내지 않는다. precision이 우선 지표인 설계에서 올바른 실패 모드다.

## 웹앱 적용

`.env`의 `JUDGMENT_BACKEND` 한 줄로 `openai` / `ollama` / `encoder`를 고른다.
셋 다 같은 `ModelCall`을 돌려주므로 `judge()`의 9단계·`judgment_logs`·
강행 전송·`report`/`evaluate`가 그대로 동작한다.

- **`judgment/backend.py`** (신규) — 라우터. torch를 지연 import해 LLM 백엔드에서는
  컨테이너에 torch가 없어도 앱이 뜬다. **import 실패도 `ModelCall(ok=False)`로 잡아**
  예외가 `judge()` 밖으로 새지 않는다 (BR-6.7).
- **`judgment/local_encoder.py`** (신규) — 어댑터. 조립된 프롬프트를 `prompt.py`의
  절 제목 상수로 되풀어 `(문맥, 후보)`를 얻는다. 후보의 화자 라벨은 떼어낸다 —
  학습 데이터의 `response`에는 라벨이 없어 붙인 채 넣으면 분포가 어긋난다.
  torch 추론을 `to_thread`로 감싸 이벤트 루프를 막지 않는다.
- 수정: `config.py`(설정 3 + 프로퍼티 2), `client.py`(2줄), `service.py`(1줄),
  `main.py`(워밍업), `try.py`(라우터 경유), `conftest.py`(테스트는 openai 고정)
- 컨테이너: `requirements-encoder.txt` 신설, Dockerfile 3곳 (이미지 +1.3GB)

**테스트 355 passed / skip 0.**

`openai`와 `ollama`가 같은 코드 경로를 쓰는 것이 결정이다 — Ollama가 OpenAI 호환
엔드포인트를 내주므로 `base_url`과 모델명만 다르고, 그래야 `client.call_model()`의
타임아웃·재시도·예산 계산(BR-6.7)이 한 벌로 남는다.

## 오늘 깨진 것 넷 — 전부 기록해둔다

### 1. 임계값 출처를 둘로 만들었다가 테스트가 잡았다

`verdict_threshold()`가 `threshold.json`을 읽게 만들면서
**"`judgment_logs.threshold`는 `AI_VERDICT_THRESHOLD`와 같다"는 불변식(BR-6.5)** 을 깼다.
`test_the_log_records_the_threshold_and_tokens`가 정확히 그것을 잡아냈다.

되돌렸다. 지금은 `AI_VERDICT_THRESHOLD` 하나가 출처이고, `threshold.json`은
**기동 시 경고에만** 쓴다. 자동으로 덮어쓰지 않는다 — 설정 파일만 보고도 어떤
기준으로 판정됐는지 알 수 있어야 한다.

> 테스트가 옳았고 설계가 틀렸다.

### 2. 판정 게이트에 절대 기준을 걸었다 (두 번)

노트북의 `학습셋 정확도 ≥ 0.90` 조건이 **건강한 학습을 실패로 판정했다.**
통제된 데이터에서 학습셋 0.90은 과적합해야 닿는 값이다. 학습 0.885 / 검증 0.890
(격차 −0.005)은 과적합이 아니라 이상적인 상태인데 `[학습 실패]`가 떴다.

`< max(0.70, 검증 − 0.02)` 상대 기준으로 바꿨다. §4와 §6 두 곳에 같은 버그가 있었다.

### 3. `pip install -U pandas`가 Colab을 깨뜨렸다

버전 지정 없는 `pandas`가 2.2 → 3.0으로 메이저 업그레이드되면서 torch가
`circular import`로 죽었다. Colab에는 이미 transformers 5.14.1이 있어 애초에
설치가 필요 없었다. 노트북 §1에서 pip을 통째로 뺐다.

### 4. CRLF를 LF로 통째로 바꿀 뻔했다

파이썬 텍스트 모드로 소스를 다시 쓰면서 줄바꿈이 전부 바뀌었다. 그대로 뒀으면
git diff에 파일 전체가 잡혔을 것이다. `newline=''`로 다시 했다.
`Dockerfile`은 LF, `.py`/`requirements.txt`는 CRLF로 파일마다 다르다.

## 확정한 것

- **운영 threshold 0.7** — 점수 간격 0.687의 안쪽. 적절 쪽 여유(0.539)가
  부적절 쪽(0.148)보다 커서 precision 우선순위에 맞는다. 기존 기본값이라
  설정 변경도 필요 없다.
- **시드 메시지는 `verification_status = disabled`** — 판정을 안 거쳤고,
  성능 집계(`ok` + `flagged_sent`)에서 제외되어 지표를 오염시키지 않는다.
- **DB 포트는 `127.0.0.1:3307`** — 원래 안 열던 것을 GUI 확인용으로 열되
  localhost에만 바인딩한다. `0.0.0.0`이면 같은 공유기의 다른 기기에서도 보인다.
  3306이 아닌 이유는 호스트 MySQL과의 충돌 회피.
- **모델 가중치는 커밋하지 않는다** — `.gitignore`에 `backend/models/` 추가.
  300MB로 GitHub 100MB 제한을 넘는다. Dockerfile이 이미지에 굽는다.

## 믿으면 안 되는 숫자 둘

- **`prec@1% = 1.000`** — FP 0에서 FPR을 0으로 계산한 결과다. 0/50의 95% 상한은
  0.060(rule of three)이고, 그 값으로 보면 **0.144**까지 떨어진다.
  실사용 기저율은 `judgment_logs.user_action`이 줘야 확정된다 (FR-7.5).
- **AUC 1.000** — `test_dataset_100`은 짝 구조가 없어 response-only만으로 0.840이
  나온다. 학습 OOF 0.832와 대비하면 이 평가셋이 **더 쉬웠다**고 보는 편이 정확하다.
