## 오늘의 핵심 — 손으로는 안 보이는 결함 넷

### 1. MariaDB 1020 — 순차 테스트는 전부 초록이었다

InnoDB는 트랜잭션의 read view가 잡힌 뒤 갱신된 행에 잠금 읽기가 닿으면 `1020`을 낸다(MySQL은 최신 커밋본을 준다). 전송의 앞 단계들이 read view를 잡아버려 **첫 번째 이후의 동시 전송이 전부 실패**했다.

> **NFR-7이 "동시 채번"을 명시 테스트 의무로 지목해두지 않았다면 데모 중에 발견했을 것이다.**

### 2. WebSocket 교체가 새 연결을 지웠다

밀려난 탭의 정리가 `unregister(user_id)`를 부르면서 **방금 자기를 교체한 연결**을 지웠다. 새 탭은 등록됐다고 믿은 채 아무것도 못 받는다. 소켓 동일성 확인으로 막았다.

### 3. 멈춘 탭 하나가 새 접속을 10초 막았다 — 라이브에서만 나왔다

| 밀려난 탭 | 새 탭의 `auth_ok`까지 |
|---|---|
| close에 응답 (정상 브라우저) | **0.0초** |
| 응답 안 함 (멈춘 탭) | **10.0초** |

가짜 소켓의 `close()`가 즉시 반환해서 단위 테스트에 안 잡혔다. **컨테이너를 띄워 raw 소켓으로 두드려서만** 나왔다. 1초 상한 → 1.00초.

### 4. `.env`만 고쳐서는 되돌아가는 설정 결함

타임아웃 4초를 `.env`에만 반영하고 코드 기본값을 5.0으로 뒀다. 리뷰어가 **그 기본값이 실제 런타임 경로임을 증명**했다 — 환경변수를 직접 주입하는 배포에서는 거기가 유일한 출처다.

> 수정 테스트는 `== 4.0`이 아니라 **부등식**으로 짰다. 숫자로 박으면 다음 사람이 값을 바꾸며 테스트도 고쳐 불변식이 사라진다.

## 오후 — 프론트 마무리와 재디자인

워크플로가 닫힌 뒤 이어서 한 것들이다.

### 깨진 흐름 넷

| 증상 | 조치 |
|---|---|
| **방을 눌러도 대화 화면으로 안 갔다** | 목록이 입장만 부르고 화면 전환을 안 했다. 앱의 주 동작인데 반쪽만 이어져 있었다 |
| 로그아웃 상태에서 4개 탭이 다 보였다(누르면 401) | 비공개 네비게이션을 로그인 시에만 렌더 |
| 로그인 후 자동 이동 없음 | 성공 시 홈(채팅 목록)으로 |
| **새로고침하면 로그인 폼이 다시 보였다** | `GET /auth/me`로 세션 복구. 401만 토큰을 지우고, 네트워크·5xx는 지키지 않는다 |

`GET /auth/me`는 U4·U5 요약이 "필요해지면 만들라"고 남긴 항목이다. 토큰을 갱신하지 않는다 — 갱신하면 무기한 세션이 되어 리프레시 토큰을 뺀 결정이 뒤집힌다.

**타입 시스템이 막아준 지점** — 헤더에 `display_name`을 쓰려다 컴파일 오류가 났다. `CurrentUser`에 그 필드가 **일부러 없다**(FR-2.4를 타입으로 막은 설계). 헤더 하나 때문에 그 방어를 풀지 않고 `username`을 썼다.

### 키만 넣으면 바로 돌게

`.env`의 키 한 줄만 바꾸면 두 명령이 즉시 돈다. 그 사이를 막던 것도 고쳤다 — 설정이 `backend/`에서 돌릴 때 저장소 루트 `.env`를 못 찾아 기동이 실패했다.

**`evaluate` 평가기가 이번 작업의 핵심이다.** `dataset/` 744행에 **판정 경로와 똑같은 프롬프트**를 돌려 precision·**recall**·F1·혼동행렬·점수 분포·난이도별 성능·임계값 스윕을 낸다.

> FR-7.5가 라이브 지표에서 recall을 "산출 불가"로 못박은 건 놓친 오발송의 모수를 모르기 때문이고 **그 판단은 여전히 옳다.** 라벨이 그 모수를 준다.

만들면서 잡은 함정 둘 — **표본이 한쪽 라벨로 쏠렸다**(CSV가 라벨별로 뭉쳐 있어 `--limit 3`이 적절 3개만 줬다. 그러면 혼동행렬의 한 축이 비어 지표가 조용히 거짓이 된다). 그리고 결정적 표집이어야 프롬프트 수정 전후를 비교할 수 있다.

### 메신저 관용구로 UI 재디자인

브랜드는 가져오지 않았다 — 로고도 특정 서비스의 색 값도 쓰지 않고, **사용자가 이미 아는 형태**만 따랐다. 내 말풍선 오른쪽·상대 왼쪽에 아바타와 별칭, 하단 탭, 안 읽은 배지, 하단 고정 입력바.

**접근성을 디자인보다 앞에 뒀다.** "색만으로 상태를 알리지 말 것"이라 "검증 안 됨"은 아이콘+문구로, 내/상대는 좌우 위치와 꼬리 방향으로 갈린다. `data-testid` 57개를 전부 유지했다.

**브라우저로 봤더니 프론트 테스트 147개가 전부 통과하는 상태에서 결함 넷이 있었다:**

1. **입력창이 사라졌다** — 전송 버튼이 `width:100%` 클래스를 써서 밀어냈다. jsdom은 레이아웃을 계산하지 않는다
2. 콜드스타트 안내가 청회색 배경에서 대비 부족
3. 날짜 구분선이 흰 글자와 대비 부족(12%→38%)
4. 탭 표시가 위치 기준을 잃어 화면 기준으로 떠 있었다

FR-2.4도 화면에서 확인했다 — 상대가 계정명이 아니라 **내가 붙인 별칭**으로 보인다.
