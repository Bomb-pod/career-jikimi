## 오늘의 핵심 — 손으로는 안 보이는 결함 넷

### 1. MariaDB 1020 — 순차 테스트는 전부 초록이었다

InnoDB는 트랜잭션의 read view가 잡힌 뒤 갱신된 행에 잠금 읽기가 닿으면 `1020`을 낸다(MySQL은 최신 커밋본을 준다). 전송의 앞 단계들이 read view를 잡아버려 **첫 번째 이후의 동시 전송이 전부 실패**했다.

> **NFR-7이 "동시 채번"을 명시 테스트 의무로 지목해두지 않았다면 데모 중에 발견했을 것이다.**

### 2. WebSocket 교체가 새 연결을 지웠다

밀려난 탭의 정리가 `unregister(user_id)`를 부르면서 **방금 자기를 교체한 연결**을 지웠다. 새 탭은 등록됐다고 믿은 채 아무것도 못 받는다. 소켓 동일성 확인으로 막았다.

### 3. 멈춘 탭 하나가 새 접속을 10초 막았다 — 라이브에서만 나왔다

| 밀려난 탭 | 새 탭의 `auth_ok`까지 |
|---|---|
| close에 응답 (정상 브라우저) | **0.0초** |
| 응답 안 함 (멈춘 탭) | **10.0초** |

가짜 소켓의 `close()`가 즉시 반환해서 단위 테스트에 안 잡혔다. **컨테이너를 띄워 raw 소켓으로 두드려서만** 나왔다. 1초 상한 → 1.00초.

### 4. `.env`만 고쳐서는 되돌아가는 설정 결함

타임아웃 4초를 `.env`에만 반영하고 코드 기본값을 5.0으로 뒀다. 리뷰어가 **그 기본값이 실제 런타임 경로임을 증명**했다 — 환경변수를 직접 주입하는 배포에서는 거기가 유일한 출처다.

> 수정 테스트는 `== 4.0`이 아니라 **부등식**으로 짰다. 숫자로 박으면 다음 사람이 값을 바꾸며 테스트도 고쳐 불변식이 사라진다.

## 내일 첫 할 일 — 하나뿐이다

`.env`의 `OPENAI_API_KEY`가 아직 자리표시자다.

```
docker compose exec app python -m app.judgment.try \
  --context "내일 회의 몇 시죠?" "10시입니다" "자료는 제가 준비할게요" \
  --candidate "오늘 저녁에 치킨 어때?"
```
