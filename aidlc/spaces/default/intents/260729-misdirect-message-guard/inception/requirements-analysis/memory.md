## Tradeoffs

- 2026-07-29T07:20:00Z — 리뷰어가 잡은 FR-7.3/7.4 모순(취소 건은 messages 행이 없어 verification_status 필터로 영원히 안 잡힘 → TP가 항상 0)을 상태 필터 수정이 아니라 **집계 대상 자체를 판정 로그로 옮기는 것**으로 해결함; verification_status는 메시지의 속성이고 판정은 메시지 없이도 일어나므로, 애초에 집계 축이 잘못 잡혀 있었다.
- 2026-07-29T07:20:00Z — `failed` 상태가 도달 불가능하다는 지적에 대해, 상태를 없애는 대신 "호출을 시도했는가"를 구분 기준으로 재정의함; failed는 시도했으나 실패한 건, degraded는 아예 시도하지 않은 건으로 나누면 여섯 값이 모두 도달 가능해지고 API 장애 빈도 집계라는 원래 의도도 살아난다.

- 2026-07-29T06:10:00Z — Q5에서 이진 판정 대신 점수+서버 임계값을 택함; 모델이 적절/부적절을 직접 말하게 하면 프롬프트가 단순하지만, 오탐이 잦을 때 조정 수단이 프롬프트 재작성뿐이다. 점수+임계값이면 precision 우선 방침을 설정값 하나로 실행할 수 있다.
- 2026-07-29T06:10:00Z — Q8(새 메시지 알림)에서 브라우저 알림 대신 배지+토스트를 권함; 브라우저 알림은 시연에서 인상적이지만 권한 요청이 거부되면 조용히 아무 일도 안 일어나 라이브 시연에서 위험하다.
