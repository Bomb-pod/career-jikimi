- A. **argon2id (`argon2-cffi`)** — 절단 없음. 규칙과 구현이 일치한다. 현재 권장 알고리즘이며 FR-1.1이 명시적으로 허용한 두 선택지 중 하나
- B. **bcrypt** — 더 오래 쓰였고 자료가 많다. 72바이트 절단을 문서화하고 수용한다
- C. bcrypt + 72바이트 초과 시 400 반환 — 절단을 없애되 BR-1.2의 "상한 없음"을 어긴다
- X. Other (please specify)

## Q1a — (Q1 후속) 비밀번호를 되돌릴 수 없게 바꿔 저장하는 방식

Q1을 다시 설명한다.

비밀번호는 DB에 그대로 저장하지 않고 **되돌릴 수 없는 형태로 바꿔서** 저장한다(FR-1.1). 그 변환 방식이 두 가지이고, 차이는 하나뿐이다:

| 방식 | 긴 비밀번호를 어떻게 다루나 |
|---|---|
| **argon2** | 길이 제한 없음. 입력한 그대로 쓴다 |
| **bcrypt** | **72바이트를 넘으면 뒷부분을 조용히 버린다.** 한글은 한 글자가 3바이트라 24글자가 한계다 |

bcrypt를 쓰면 25글자짜리 한글 비밀번호를 만든 사용자가 **실제로는 앞 24글자로만 로그인되며, 본인은 그 사실을 알 수 없다.** `business-rules.md` BR-1.2가 "비밀번호 상한은 두지 않는다"고 정해두었으므로 이 절단은 그 규칙과 어긋난다.

둘 다 안전성은 충분하고 FR-1.1이 명시적으로 허용한 선택지다. 구현 난이도도 같다.

- A. **argon2 (추천)** — 규칙과 구현이 일치한다. 잘리는 경우가 없다
- B. bcrypt — 자료가 더 많다. 24글자 절단을 알고 수용한다
- X. Other (please specify)

[Answer]: A. argon2 (추천) — 2026-07-30, **Mode:** guided
